# Decisions and Assumptions

This document records the architectural choices, mathematical definitions, business logic rules, and assumptions adopted in the implementation. Every decision directly cites or aligns with the recruitment requirements.

| Topic | Decision / Assumption | Rationale & Source Reference | Risk / Mitigation |
|---|---|---|---|
| **Python Environment** | Python 3.14+ targeting standard library for core engine (`sqlite3`, `json`, `csv`, `random`, `math`, `dataclasses`, `argparse`). `pytest` for testing; `streamlit` and `pandas` for demo dashboard. | CHALLENGE §Part B (Suggested tech stack), FAQ §8. Eliminating heavy runtime dependencies from core engine guarantees $0 cost, zero compilation errors, and high portability across Windows environments. | Verified that Python 3.14 runs standard library and pytest cleanly. Streamlit is isolated to `app.py`. |
| **Database Engine & Settings** | Local SQLite 3 relational database. Enforce `PRAGMA foreign_keys = ON;` on every single connection immediately after opening. | CHALLENGE §Part B (Core functional requirements), PROMPT §Engineering standards. Enforces relational integrity at the storage layer. | Foreign keys can reject invalid fixtures if executed in standard mode; isolated anomaly tests run with controlled validation passes or in designated validation fixtures. |
| **Identifier Schemes** | Formats match official specifications:<br>- Learner: `LRN-XXXXXX` (6-digit zero padded)<br>- Course: `CRS-XXXXXX`<br>- Skill: `SKL-XXXXXX`<br>- ContentItem: `CNT-XXXXXX`<br>- Attempt: `ATT-<learner_id>-XXXXXX`<br>- LearningPath: `PATH-2026-XXXXXX`<br>- Assessment: `ASM-XXXXXX`<br>- Recommendation: `REC-XXXXXX` | CHALLENGE §Example identifier formats. Ensures consistency, readability, and compatibility with validation rules. | Regex pattern validation in `src/validator.py` prevents format drift. |
| **Mastery Calculation Formula** | Mastery of learner $L$ for skill $S$ at cutoff time $t$ is defined as a recency-weighted exponential moving average (EWMA) of assessment scores for content items addressing $S$, bounded in $[0.0, 1.0]$. Default prior mastery is 0.0. | CHALLENGE §4. A time-decayed scoring model accurately reflects retention and practice while preventing sudden drops from single outlier attempts. | Explicitly tested with synthetic timestamp sequences to verify monotonicity and decay. |
| **Temporal Safety Gate** | Any attempt or assessment where `end_time > t_as_of` is strictly ignored in mastery computation and recommendation ranking. | CHALLENGE §4 (Temporal cutoff). Prevents data leakage where future student activity influences historical recommendations. | Dedicated unit test (`test_future_attempt_leakage_prevented`) asserts identical mastery before and after future attempt insertion. |
| **Prerequisite Threshold & Gating** | Prerequisite satisfaction requires $Mastery(L, PrereqSkill, t) \ge \text{min\_mastery\_threshold}$ (default 0.70). If any direct prerequisite is below threshold, the dependent skill is disqualified from content recommendations. | CHALLENGE §6. Enforces hard pedagogical prerequisites rather than soft preferences. | Tested against cyclic graphs and missing prerequisites. Topological validation ensures no cyclic deadlocks in prerequisite DAG. |
| **Recommendation Ranking Formula** | Multi-factor explainable score:<br>$\text{Score} = 0.45 \cdot \text{SkillGap} + 0.35 \cdot \text{DifficultyFit} + 0.20 \cdot \text{ContentRelevance}$<br>Where $\text{SkillGap} = 1.0 - \text{Mastery}$, $\text{DifficultyFit} = 1.0 - \frac{|\text{LearnerLevel} - \text{ContentDiff}|}{4.0}$. Deterministic tie-breaking on `content_id`. | CHALLENGE §7, §8. Transparent, explainable weights allow generation of distinct reason codes (`SKILL_DEFICIT`, `DIFFICULTY_ALIGNMENT`, `CURRICULUM_PRIORITY`). | Weights are configurable in `src/config.py`. |
| **Anomaly Isolation & Fixtures** | Clean baseline generator produces 100% valid data. Injected anomalies (prereq violation, timestamp inversion, orphaned skill reference, future leakage, zero-progress loop) are generated into separate fixture datasets and cataloged in `data/ground_truth/anomalies.json`. | CHALLENGE §12, §13, PROMPT §Core implementation. Avoids contaminating baseline datasets while providing ground-truth labels for evaluation. | Ground-truth fixtures are loaded during validation and pytest to measure precision/recall of the anomaly detector. |
| **Synthetic Scale & Performance** | Generator uses batching (`executemany`, chunk size 10,000) and in-memory caches of entity IDs to support scaling from small (50 learners, 500 attempts) to target scale (10,000 learners, 500,000 attempts) without RAM exhaustion. | CHALLENGE §Target synthetic-data volumes. SQLite memory-friendly streaming prevents out-of-memory errors on Windows. | Benchmarked runtime and peak memory recorded in evaluation reports. |
| **Export Formats** | Clean datasets and recommendations are exported to CSV (RFC 4180 format), JSON (structured hierarchical/tabular), and SQL (`INSERT` dump script) in `exports/`. | CHALLENGE §3. Meets all multi-format export requirements. | Validated with automated round-trip parsing tests. |
